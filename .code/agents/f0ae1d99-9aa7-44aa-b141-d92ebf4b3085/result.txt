### Root Cause Analysis

**File & Logic Failure:**
In `src/ClassicUO.Client/Network/PacketHandlers/Helpers/ItemHelpers.cs` (Line 117), the code performs a direct Gump lookup:
```csharp
GridContainer gridGump = UIManager.GetGump<GridContainer>(containerSerial);
if (gridGump != null)
    gridGump.RequestUpdateContents();
```
Because tabbed sub-containers do not have their own Gump registrations (they are managed internally by the root `GridContainer` Gump), `UIManager.GetGump` returns `null` for any serial representing a tab. Consequently, the UI remains stale until a manual tab switch forces a rebuild.

**Reproduction Sequence:**
1. Enable Grid Layout and Grid Container Tabs.
2. Open a backpack (`GridContainer`) and open a pouch inside it as a tab.
3. With the pouch tab active, drop an item into it.
4. `AddItemToContainer` is called for the pouch serial; it fails to find the Gump and skips the update.

### Proposed Fixes

#### Option 1: Robust Routing (Recommended)
Systematically replace direct `GridContainer` updates with the `GridContainer.NotifyContainerUpdate(world, serial)` helper. This helper correctly identifies if a container is a tab and rebuilds the appropriate `SlotManager`.

**Target Changes:**
- **`ItemHelpers.AddItemToContainer`**: Replace lines 117–121 with `GridContainer.NotifyContainerUpdate(world, containerSerial);`.
- **`EquipItem.cs`**: Add `GridContainer.NotifyContainerUpdate(world, item.Container);` at line 27 to handle items being removed from/added to containers via equipment changes.
- **`DenyMoveItem.cs`**: Add `GridContainer.NotifyContainerUpdate(world, Client.Game.UO.GameCursor.ItemHold.Container);` at line 58.
- **`ObjectHelpers.cs`**: Add `GridContainer.NotifyContainerUpdate(world, Client.Game.UO.GameCursor.ItemHold.Container);` at line 43.

#### Option 2: Minimal Risk
Only apply the fix to `ItemHelpers.AddItemToContainer`, as this covers the majority of user-reported issues (dropping and looting).
