## Root Cause Analysis: Auto-Looter Targeting House Items

### 1. Entry Conditions for Ground-Item Scavenging

The scavenger system tracks ground items via two paths:

- **`OnItemCreatedOrUpdated`** (`AutoLootManager.cs:482-510`): Any new/updated item within 20 tiles that passes `IsTrackableGroundItem()` is added to `_nearbyGroundItems`. If within `AutoOpenCorpseRange`, it's immediately checked for looting.
- **`OnPositionChanged`** (`AutoLootManager.cs:417-473`): Every time the player moves, all tracked nearby items within `AutoOpenCorpseRange` are re-evaluated via `CheckAndLoot()`.

Both gates depend on `IsTrackableGroundItem`:

```csharp
// AutoLootManager.cs:152-155
internal static bool IsTrackableGroundItem(Item item)
{
    return item != null && item.OnGround && !item.IsCorpse && !item.IsLocked;
}
```

### 2. The Bug: `IsLocked` Heuristic is Fatally Narrow

**`Item.cs:61`:**
```csharp
public bool IsLocked => (Flags & Flags.Movable) == 0 && ItemData.Weight > 90;
```

This requires **both** conditions:
- The `Movable` flag (0x20) is NOT set, **AND**
- The item's static tile data weight is > 90

**The problem:** Most items in UO weigh far less than 90. Potions, reagents, scrolls, jewelry, weapons, armor, gold piles, food — all have `ItemData.Weight <= 90`. When locked down in a house, these items lose the `Movable` flag from the server, but they're NOT caught by `IsLocked` because they fail the weight check.

**Contrast with `IsMovable`** (`Item.cs:63`):
```csharp
public bool IsMovable => (Flags & Flags.Movable) != 0;
```

This is the correct check. The UO server sends `Flags.Movable` (0x20 from `EntityFlags.cs:17`) based on whether the viewing player can actually pick up the item. Locked-down / secured items have this cleared server-side.

### 3. Why It Retries Repeatedly

Three compounding factors:

**a) Ground items explicitly bypass cooldowns** (`AutoLootManager.cs:124-129, 639-640`):
```csharp
// Line 124-129: cooldown check skips ground items
if (!item.OnGround && _lootCooldowns.TryGetValue(...))

// Line 639-640: cooldown only SET for non-ground items
if (!moveItem.OnGround)
    _lootCooldowns[moveItem.Serial] = Time.Ticks + 30000;
```

**b) `_recentlyLooted` clears every 5 seconds** (`AutoLootManager.cs:546-549`):
```csharp
if (Time.Ticks > _nextClearRecents)
{
    _recentlyLooted.Clear();
    ClearMatchCache();
    _nextClearRecents = Time.Ticks + 5000;
```

**c) Every player movement re-evaluates** (`AutoLootManager.cs:456-467`):
After `_recentlyLooted` clears, the next movement triggers `CheckAndLoot` on all nearby tracked items again.

**Result:** The auto-looter sends a pickup+drop packet to the server every ~5 seconds for each house item that matches a loot entry. The server silently rejects it, but the client never learns.

### 4. `Scavenge` Default Makes This Pervasive

`AutoLootManager.cs:1470`:
```csharp
public bool Scavenge { get; set; } = true;
```

**Every loot entry defaults to scavenging ground items.** The `IsOnLootList` method (lines 224-238) only skips ground items if `entry.Scavenge` is `false`. So unless the user has deliberately turned off Scavenge on every entry, any matching house item triggers the bug.

### 5. User-Config Issue vs Real Code Bug

| Factor | Verdict |
|--------|---------|
| `IsLocked` weight > 90 heuristic | **Code bug** — fails for the vast majority of items |
| No `IsMovable` check on scavenger path | **Code bug** — the correct flag exists but isn't used |
| No ground-item cooldown after server rejection | **Code bug** — causes spam |
| `Scavenge = true` default | **Design choice** but amplifies the bug |
| No house detection | **Missing feature** but secondary to the flag check |

**This is primarily a code bug**, not a user config issue.

### 6. Server-Specific Considerations

Some free shards may not set `Flags.Movable` consistently for all pickupable ground items (e.g., freshly spawned loot, treasure map items). On those servers, switching from `!IsLocked` to `IsMovable` could cause false negatives where legitimate loot is skipped. OSI/standard servers set the flag correctly.

### 7. Proposed Fixes

**Fix 1: Minimal — Use `IsMovable` in `IsTrackableGroundItem`** (LOW risk, HIGH impact)

```csharp
// AutoLootManager.cs:152-155
internal static bool IsTrackableGroundItem(Item item)
{
    return item != null && item.OnGround && !item.IsCorpse && item.IsMovable;
}
```

Also update the parallel check at line 444:
```csharp
if (item == null || !item.OnGround || !item.IsMovable || item.IsCorpse)
```

- **Tradeoff:** On non-standard servers that don't set `Movable` for droppable ground items, scavenging would stop working for those items. This is unlikely but possible.
- **Risk:** Low. `Flags.Movable` is the canonical UO protocol indicator.

**Fix 2: Add ground-item cooldown on failed loot** (LOW risk, MEDIUM impact)

When a ground item's `MoveRequest` executes and the server rejects it (or when the item is still present after N seconds), add it to `_lootCooldowns` with a long TTL (e.g., 60s). This prevents spam even if the tracking heuristic has gaps.

- **Tradeoff:** Requires hooking server rejection packets or using a timeout heuristic.
- **Risk:** Low, but more complex to implement because the current `MoveRequest.Execute()` is fire-and-forget.

**Fix 3: House detection guard** (MEDIUM risk, HIGH impact)

Use `HouseManager.EntityIntoHouse()` or check if the item's coordinates fall within a known house multi's bounds. Skip scavenging for items inside a house.

```csharp
internal static bool IsTrackableGroundItem(Item item)
{
    if (item == null || !item.OnGround || item.IsCorpse || !item.IsMovable)
        return false;
    // Skip items inside known houses
    foreach (var house in item.World.HouseManager.Houses)
        if (item.World.HouseManager.EntityIntoHouse(house.Key, item))
            return false;
    return true;
}
```

- **Tradeoff:** Iterating houses on every item check has performance cost. Could be mitigated with a spatial lookup. Also, items legitimately dropped inside your OWN house should still be scavengeable.
- **Risk:** Medium — false negatives for items you dropped in your own house.

### Recommendation

**Apply Fix 1 first** — it's a one-line change, directly addresses the root cause, and `IsMovable` is exactly what the server tells us. Fix 2 is a good defensive addition but can come later. Fix 3 is overkill unless Fix 1 proves insufficient on specific shards.
