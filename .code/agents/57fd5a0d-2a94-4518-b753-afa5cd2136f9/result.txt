Verified: your “known observation” is correct, and it explains the reported behavior.

**Root Cause(s)**
1. **Packet-driven add/update path only refreshes direct `GridContainer` gumps, not tab-hosted containers.**  
   In `ItemHelpers.AddItemToContainer`, refresh logic does:
   - `UIManager.GetGump<GridContainer>(containerSerial)` then `RequestUpdateContents()`  
   - but **does not route to parent tabbed gump** when `containerSerial` is a tab child  
   See `src/ClassicUO.Client/Network/PacketHandlers/Helpers/ItemHelpers.cs:117` and `src/ClassicUO.Client/Network/PacketHandlers/Helpers/ItemHelpers.cs:119`.

2. **Tabbed architecture expects routed updates via parent gump.**  
   `GridContainer` already has the correct routing API:
   - `NotifyContainerUpdate(...)` resolves direct gump or parent tab host  
   - `FindParentGridContainer(...)` walks container ancestry  
   - `RequestUpdateContentsForTab(...)` updates active tab (`InvalidateContents = true`) or rebuilds inactive tab immediately  
   See `src/ClassicUO.Client/Game/UI/Gumps/GridContainer.cs:1455`, `src/ClassicUO.Client/Game/UI/Gumps/GridContainer.cs:1427`, `src/ClassicUO.Client/Game/UI/Gumps/GridContainer.cs:1475`.

3. **Asymmetry in code paths causes “remove looks live, add looks stale.”**  
   Removal paths already call `GridContainer.NotifyContainerUpdate(...)`:
   - `src/ClassicUO.Client/Network/PacketHandlers/DeleteObject.cs:68`
   - `src/ClassicUO.Client/Game/World.cs:380`
   - `src/ClassicUO.Client/Game/World.cs:635`  
   Add/update path (`AddItemToContainer`) does not, causing stale tab contents until a manual tab switch triggers rebuild.

4. **Why tab switch “fixes” it visually:**  
   `SwitchToTab(...)` always sets `InvalidateContents = true`, and `UpdateItems()` rebuilds from world state.  
   See `src/ClassicUO.Client/Game/UI/Gumps/GridContainer.cs:1424` and `src/ClassicUO.Client/Game/UI/Gumps/GridContainer.cs:865`.

**Repro Event Sequence**
1. Open root container `A` as `GridContainer`; open child `B` as a tab and view tab `B`.
2. Drop/move item into `B` (or server updates an existing item in `B`).
3. Server sends `0x25/0x3C`-style contained-item update; handler calls `ItemHelpers.AddItemToContainer(...)`.
4. World model updates (`container.PushToBack(item)`), but UI refresh checks only `GetGump<GridContainer>(B)` and finds none (because only `A` has a gump).
5. No `InvalidateContents` on host gump `A` for active tab `B`; display remains stale.
6. User switches tabs; `SwitchToTab(...)` invalidates and rebuilds, so changes appear.

   Tradeoff:
   - Very low risk, localized.
