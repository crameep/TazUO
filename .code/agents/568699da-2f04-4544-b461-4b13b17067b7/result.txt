**Summarizing autoloot retry issues**
[2026-02-28T21:02:38] codex

Likely diagnosis: this is a mix of **expected-by-current-config** behavior and a **real retry/eligibility bug** in the scavenger path.

1. **When AutoLoot enqueues ground/scavenger items**
1. `OnItemCreatedOrUpdated` tracks ground items when scavenger is enabled, then immediately calls `CheckAndLoot` if in range: `src/ClassicUO.Client/Game/Managers/AutoLootManager.cs:495`, `src/ClassicUO.Client/Game/Managers/AutoLootManager.cs:502`, `src/ClassicUO.Client/Game/Managers/AutoLootManager.cs:503`.

4. `AutoLootConfigEntry.Scavenge` defaults to `true`, so entries created for corpse looting also scavenge ground unless user disables per entry: `src/ClassicUO.Client/Game/Managers/AutoLootManager.cs:1470`.
5. Scavenger itself is default-enabled in profile defaults: `src/ClassicUO.Client/Configuration/Profile.cs:680`.

2. **Current guards against unlootable/locked/secured/house items**
1. Tracking guard is only `OnGround && !IsCorpse && !IsLocked`: `src/ClassicUO.Client/Game/Managers/AutoLootManager.cs:152`.
2. `IsLocked` is heuristic: `(Flags & Movable)==0 && ItemData.Weight > 90`: `src/ClassicUO.Client/Game/GameObjects/Item.cs:61`.
3. There is no explicit house-permission/secured-container check in AutoLoot.
4. AutoLoot move execution sends pickup/drop directly via `MoveRequest.Execute` with no pre-check equivalent to manual `GameActions.PickUp`: `src/ClassicUO.Client/Game/Managers/Structs/MoveRequest.cs:32`, `src/ClassicUO.Client/Game/Managers/Structs/MoveRequest.cs:34`.
5. Manual drag path has stricter guard (`item.OnGround && (item.IsLocked || distance)`) but AutoLoot bypasses it: `src/ClassicUO.Client/Game/GameActions.cs:815`.

3. **Why it can repeatedly try in a house**
1. House-secured/locked-down items may not satisfy this client-side `IsLocked` heuristic, so they enter scavenger tracking anyway.
2. If the server denies pickup (ownership/security rules), `DenyMoveItem` restores cursor/item but does not notify AutoLootManager to back off that ground item: `src/ClassicUO.Client/Network/PacketHandlers/DenyMoveItem.cs:14`.

4. **Most likely responsible conditions**
1. Weak lockability check: `src/ClassicUO.Client/Game/GameObjects/Item.cs:61`.
2. Scavenger admission gate too broad: `src/ClassicUO.Client/Game/Managers/AutoLootManager.cs:152`.
3. Ground retry cadence: `src/ClassicUO.Client/Game/Managers/AutoLootManager.cs:547` with no ground cooldown (`src/ClassicUO.Client/Game/Managers/AutoLootManager.cs:639`).

5. **User-config vs code bug**
1. User-config side (likely): scavenger enabled + entries still `Scavenge=true` for common graphics -> client tries house ground items that match.
2. Code-bug side (also likely): repeated retries on denied ground items due missing denial-aware backoff and limited lock/permission gating.
