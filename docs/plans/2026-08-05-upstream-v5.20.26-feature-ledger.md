- Target policy: upstream wins when it is equal or better. Fork behavior is adapted only when
  it adds capability, measurably improves behavior, or preserves an established workflow.

## Disposition legend

- **Accept upstream**: do not port the fork implementation.
- **Adapt fork**: preserve the capability on top of the upstream architecture.
- **Retain fork**: the implementation is sufficiently isolated and remains the preferred one.
- **Drop**: intentionally remove obsolete, diagnostic, duplicated, or inferior behavior.
- **Investigate**: evidence is not yet strong enough for a decision.

Verification states are **Not started**, **Code reviewed**, **Automated**, and **Manual**.
"Automated" and "Manual" require recorded evidence in the final section.

## Acceptance checklist

The integration is not complete until the following are evidenced:

- [ ] The integration branch builds from a clean checkout with required submodules.
- [ ] The complete unit-test suite passes.
- [ ] Legacy fork configuration migrates without losing selected loot lists/profiles, exclusions,
      destinations, pinned buttons, grid tabs, skill view preferences, tome definitions, combat
      settings, UI scale, or colorblind settings that remain supported.
- [ ] Auto-loot priorities, selected/enabled lists, wildcard/regex rules, per-entry scavenging,
      exclusions, destinations, retry behavior, and queue fairness work in game.
- [ ] Grid bands/sorts/highlights coexist with tabs, capacity display, pinned buttons, treasure tint,
      and quick drop.
- [ ] Organizer external destinations, auto-walk, and tome workflows work and can be cancelled safely.
- [ ] Combat meter, per-target/timeline data, export, kill tracking, and HUD survive relog/disconnect
      lifecycle transitions without stale data or crashes.
- [ ] Skills retain upstream Myra functionality and persist the selected sort/group settings.
- [ ] `PreTarget` compatibility and `UseObjectOnTarget` work from both supported scripting runtimes,
      with regenerated docs matching the public API.
- [ ] Upstream Myra options, SQL-backed settings, TazLang, modular grids, pathfinding, and renderer
      features remain functional.
- [ ] No MobileUO/iOS runtime work is introduced.
- [ ] The final diff and this ledger are reviewed with the user before any push or main update.
